# Custom OpenCode CV Agents Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add three project-scoped OpenCode agents and two shared guideline skills that audit/maintain the CV, write tailored cover letters, and produce tailored CV variants.

**Architecture:** `.opencode/agents/*.md` define agents (YAML frontmatter = config, body = system prompt); `.opencode/skills/*/SKILL.md` hold researched guidance the agents load on demand. No code, no build changes. The tailored-CV agent renders through the existing scripts by writing a transient variant into the already-gitignored `public/cv/`.

**Tech Stack:** OpenCode V2 agent/skill config (Markdown + YAML frontmatter), this repo's Node/Astro build scripts.

**Spec:** `docs/superpowers/specs/2026-10-03-cv-agents-design.md`

## Global Constraints

- **Markdown-only change.** No new scripts, no dependency changes, no build changes. (One small wording edit to `AGENTS.md` is in scope.)
- **No TDD.** The user explicitly waived test-driven development for this documentation-only work. "Test" steps become verification steps (static parse, discovery, artifact assertions), not failing-test-first cycles.
- **Do not commit the user's pre-existing uncommitted work.** `src/components/Layout.astro`, `src/pages/showcase/*`, `src/styles/global.css`, and `src/scripts/showcase.ts` are already modified/untracked. Only `git add` the exact files each task creates or edits.
- **Never commit or push** from within an agent; `git push*` is denied in every agent's permissions.
- **The most recent position has no end date.** Never add one, anywhere.
- Agent frontmatter fields: `description`, `mode: all`, `permissions`. Do not pin a `model`.
- Any frontmatter string containing a colon must be quoted.
- Rule ordering in `permissions`: OpenCode V2 applies the **last matching rule**, so broad rules come first and exceptions last.
- Skill frontmatter fields: `name`, `description`.

## Review Focus

The failure modes most likely to bite a person using these agents, each pinned to a test/task below:

1. **New agents not discovered until restart** — `opencode run` against a cached background server may not see `.opencode/agents/`. Mitigated by using `--standalone` in every discovery probe (Task 3–5, Task 7).
2. **Permission rule ordering reversed** — a `deny` placed after an `allow` silently blocks the command. Pinned by a reviewer reading each frontmatter list top-to-bottom (Tasks 3–5).
3. **Frontmatter breaks on an unquoted colon** in a `description`. Pinned by the YAML-parse check in every task.
4. **Tailored-CV agent writing outside `public/cv/`**, touching tracked files. Pinned by the `git status --porcelain` assertion in Task 5 and Task 7.
5. **Skill not actually loadable** by an agent (wrong path or missing frontmatter). Pinned by the agent probes in Tasks 3–5 that require the agent to load the skill.

### Task 1: CV-writing skill

**Files:**
- Create: `.opencode/skills/cv-writing/SKILL.md`

**Interfaces:**
- Produces: skill id `cv-writing`, discoverable and loadable via the skill tool; consumed by `cv-maintainer` (Task 3) and `tailored-cv` (Task 5).

- [ ] **Step 1: Research and curate the guidelines**

Fetch and read at least three reputable sources on technical-résumé writing (for example Google's XYZ bullet guidance, the Tech Interview Handbook résumé guide, and a university career-service or established developer-CV guide). Record the source URLs in the skill itself. Do not invent advice.

- [ ] **Step 2: Write the skill**

Create `.opencode/skills/cv-writing/SKILL.md` with frontmatter:

```yaml
---
name: CV writing
description: Researched guidance and repo rules for reviewing, writing, and tailoring this CV
---
```

Body sections, in order:
1. **When to use** — reviewing or editing `src/content/cv/en.yaml`; tailoring for a posting.
2. **Structure & ordering** — summary, key achievements, skills, experience (reverse-chronological), education, languages; lead with the most relevant evidence.
3. **Achievement bullets** — formula `action verb → scope/context → technology → measurable outcome`; quantify; one idea per bullet; no responsibility-only lines.
4. **Language** — strong active verbs, past tense for past roles, no first person, no filler adjectives, consistent terminology.
5. **Detail vs noise** — specifics over adjectives; expand only what a posting needs.
6. **ATS-safe phrasing** — standard section names, plain structure, keyword alignment with target roles.
7. **Common failure modes** — a short list.
8. **Repo guardrails (verbatim, must appear)** — the most recent position has no end date; no salary, colleague names, vulnerability details against named employer systems, internal hostnames, or phone number (email only); keep `en.yaml`, `cover-letters/applicant.yaml`, and the showcase consistent; the repo is public, so everything written is published.
9. **Review checklist** — a checkable list a reviewer runs.
10. **Sources** — the URLs from Step 1.

- [ ] **Step 3: Verify the skill is well-formed**

Run:
```bash
node -e "const fs=require('fs');const s=fs.readFileSync('.opencode/skills/cv-writing/SKILL.md','utf8');const m=s.match(/^---\n([\s\S]*?)\n---/);if(!m)throw new Error('no frontmatter');const y=require('yaml').parse(m[1]);if(!y.name||!y.description)throw new Error('missing name/description');console.log('OK',y.name)"
```
Expected: `OK CV writing`

- [ ] **Step 4: Commit**

```bash
git add .opencode/skills/cv-writing/SKILL.md
git commit -m "feat(agents): add cv-writing skill"
```

```yaml
    resource: "npx astro build"
    effect: allow
  - action: edit
    resource: "*"
    effect: deny
  - action: edit
    resource: "src/content/cv/**"
    effect: allow
  - action: edit
    resource: "src/content/profiles/**"
    effect: allow
  - action: edit
    resource: "src/content/showcase/**"
    effect: allow
  - action: edit
    resource: "public/media/projects/**"

    effect: allow

    resource: "*"

    resource: "*"

```

Body must contain these sections, in order:
1. **Role** — one paragraph: you own the canonical CV and its consistency.
2. **Load the skill** — instruct it to load the `cv-writing` skill before auditing or editing.
3. **Mode A: Audit** — read `src/content/cv/en.yaml`, `cover-letters/applicant.yaml`, `src/content/showcase/projects_en.yaml` and the case studies; report findings grouped by severity with `file:line`; when asked (and only then) apply agreed fixes.
4. **Mode B: Project intake** — given a path, git URL, or web URL, read the project, extract only evidenced skills/technologies, judge whether it merits a showcase card, and reconcile into `src/content/cv/en.yaml`, `src/content/showcase/projects_en.yaml`, and the case study. Never fabricate experience, metrics, or technologies; report gaps instead.
5. **Guardrails (verbatim)** — the most recent position has no end date; no salary, colleague names, vulnerability details against named employer systems, internal hostnames, or phone number (email only); keep the three sources consistent; the repo is public.
6. **Validation** — after any edit, run `npm run cv:build` then `npx astro build` and report the result.
7. **Boundaries** — do not edit `cover-letters/applications/**`; never commit or push.
